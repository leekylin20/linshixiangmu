File to Markdown

高风险批量转写工具的任务包说明页

file-to-md 会递归扫描目录，把 PDF 转成 Markdown， 并把音频 / 视频转成 16k 单声道片段后调用转写接口。它依赖 OPENAI_API_KEY、OPENAI_BASE_URL 和 ffmpeg， 适合做高风险边界展示，但本页只生成任务包，不执行扫描、不转写、不写文件。

入口 node index.js --input ... --dry-run
高风险点 API Key、网关、音视频转写、递归扫描
本页边界 只展示，不执行，不联网
任务包预览 no execute / no upload

目标

对目录中的 PDF / 音频 / 视频文件做批量转 Markdown 的只读风险展示。

允许范围

只读查看 README、PROJECT-LOG、NEXT-STEPS、index.js 和 package.json；只生成任务包和运行记录。

禁止事项

不执行扫描、不调用 OpenAI、不读取 API Key、不写输出、不创建 _run-summary.json、不上传、不自动化批处理。

关键依赖

OpenAI 音频转写接口、ffmpeg、pdf-parse、Node CLI、递归目录扫描。

建议验证

先做 dry-run，再做极小样本，再决定是否扩大；对外版必须脱敏路径和密钥字段。

这是任务包展示，不是执行按钮，也不是可点击操作区。

README运行方式与限制
PROJECT-LOG迁移与修复记录

推荐流程

  1. 1只读核对

    确认 README、PROJECT-LOG、NEXT-STEPS、index.js 和 package.json。

  2. 2风险定级

    把 API Key、转写、递归扫描、输出目录和网关依赖单独标高风险。

  3. 3任务包

    只生成任务包、运行记录和审查说明，不触发真实处理。

  4. 4后续再测

    若要执行，必须单独走 dry-run 和小样本路线。

输出边界

  • --output 默认指向 output/，但本页不写入。
  • 音视频转写结果原本会写入 .md 和 _run-summary.json，本页不生成这些文件。
  • PDF 路径仍可提取文本，但本页不解析任何输入文件。
  • 默认支持递归扫描，但本页不扫描目录。

运行记录必须写明

审核边界

  • 本页是静态说明页，不执行扫描、转写或写盘。
  • 不读取 secret、API Key、Cookie 或账号登录态。
  • 不联网、不上传、不自动发布、不调用外部服务。
  • 高风险仅用于说明，不进入真实处理链路。
  • 对外展示前必须脱敏本地绝对路径和示例网关配置。

为什么适合做样例 04

  • 这是第一个明确高风险但不执行的样例，能验证“风险展示页”和“任务包”边界。
  • API Key、Base URL、ffmpeg 和转写链路都很明确，适合做审核示范。
  • 可以把“可执行”与“可展示”拆开，防止高风险工具被误当成低风险工具。
  • 它的产物类型清楚：任务包、运行记录、审查说明，而不是执行结果。

终审 checklist

  • 用途限定为内部 artifact。
  • 无执行入口、无上传、无外部资源、无实时通信通道。
  • 风险触点已明确标注为高风险，仅作展示。
  • 运行记录写明未执行真实工具、未读取 secret。
